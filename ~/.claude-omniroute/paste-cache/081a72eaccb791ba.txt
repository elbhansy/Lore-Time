Next: M3.0 — Canonical Analytics & Derived Knowledge

Goal: Build deterministic, read-only analytical projections derived exclusively from the Canonical Event Store.

Important: M3.0 must never become a new source of truth. Every metric must be reproducible from canonical events.

M3.0 Scope
M3.0.1 — Analytics Domain Contracts
packages/domain/analytics/
├── AnalyticsQuery
├── AnalyticsMetric
├── AnalyticsSnapshot
├── CharacterActivityMetric
├── RelationshipMetric
├── EventDistributionMetric
└── AnalyticsReader

Requirements:

Immutable DTOs.
No ORM dependencies.
No direct mutation APIs.
Explicit series_id / time-range scoping.
Deterministic metric definitions.
M3.0.2 — Event Statistics Projection

Derive:

Total Events
Events by Chapter
Events by Type
Events by Sequence
Events by Entity
Relationships by Type

Example:

{
  "total_events": 12430,
  "chapters": 85,
  "event_types": {
    "COMBAT": 3200,
    "DIALOGUE": 5100
  }
}
M3.0.3 — Character / Entity Activity

Calculate:

entity
├── event_count
├── subject_count
├── target_count
├── relationship_count
├── chapters_present
└── first_seen / last_seen

This should reuse the canonical entity and relationship projections rather than duplicate resolution logic.

M3.0.4 — Relationship Analytics

Provide:

Relationship frequency
Most connected entities
Relationship distribution
Entity interaction frequency
Chapter-by-chapter relationship changes

Example:

Alice
├── KNOWS      14
├── ATTACKED    7
└── MEMBER_OF   2
M3.0.5 — Analytics API
GET /api/v1/series/{series_id}/analytics/overview
GET /api/v1/series/{series_id}/analytics/events
GET /api/v1/series/{series_id}/analytics/entities/{entity_id}
GET /api/v1/series/{series_id}/analytics/relationships

All endpoints must:

enforce existing authorization;
read only canonical/derived data;
use deterministic ordering;
support bounded pagination where applicable.
